# Семейная синхронизация care-notes

Сервис рассчитан на одну семью (до 10 устройств). Он хранит один зашифрованный архив с назначениями, посещениями и документами. Телефоны шифруют его AES-256-GCM со случайным ключом семьи. Сервер не получает ключ и не распознаёт медицинские данные. HTTPS обязателен; VPN для подключения не нужен.

## Установка на VPS

Нужны Docker с Compose, публичный IP VPS и один свободный TCP-порт, например 8443. Порты 80 и 443 не нужны. VPN не требуется. Порт Python 8080 доступен только внутри Docker.

1. Скопировать каталог `server` на VPS. Скопировать `.env.example` в `.env`.
2. Записать публичный IP в `SERVER_ADDRESS` (без `https://` и порта), например `203.0.113.10`. Записать свободный порт в `HTTPS_PORT`, например `8443`. `LISTEN_ADDRESS=0.0.0.0` разрешает внешние подключения. Открыть выбранный TCP-порт в сетевом экране VPS и у провайдера.
3. Сгенерировать секрет командой `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`, записать его в `SETUP_SECRET`; ограничить доступ к `.env`: `chmod 600 .env`. Не добавлять файл в Git.
4. Запустить из каталога сервера: `docker compose up -d --build`. Caddy автоматически создаёт собственный центр сертификации и HTTPS-сертификат для указанного IP. Проверить `docker compose ps` и `docker compose logs --tail 30`.
5. Забрать корневой сертификат командой `docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt ./care-root.crt`. Передать **только этот публичный файл** на телефон владельца через доверенный канал, например USB или лично. Файлы `root.key` и остальные закрытые ключи остаются на сервере. Для проверки отпечатка на VPS: `openssl x509 -in care-root.crt -noout -fingerprint -sha256`.
6. На первом телефоне: «Семейный доступ» → адрес `https://ВАШ_IP:8443`, «Выбрать сертификат сервера» → `care-root.crt`, сверить SHA-256 с VPS, ввести секрет первого подключения и название телефона → «Создать семейный доступ». Первоначальная настройка после создания владельца закрывается. Сертификат доверяется только соединению этого приложения с сервером; системная установка сертификата Android не нужна.
7. Сразу скопировать **код восстановления** в защищённое место. Его нельзя хранить только на этом же телефоне: без ключа данные сервера невозможно восстановить.
8. Владелец создаёт приглашение с правом редактирования, передаёт код дочери. На её телефоне вставить код в том же разделе, указать название устройства и подключить. Приглашение одноразовое, действует 10 минут; в нём уже находятся адрес с портом и публичный сертификат. Код содержит ключ семьи — передавайте только нужному человеку.

HTTPS проверяет цепочку сертификатов и IP сервера. Неподходящий или недоверенный сертификат не принимается. Корневой сертификат и закрытые ключи Caddy находятся в томе `caddy_data`: сохраняйте этот том при обновлениях (`docker compose down` без `-v`). Если удалить том, получится другой центр сертификации и сохранённые подключения перестанут доверять серверу. Архивируйте `caddy_data` безопасным способом вместе с серверными резервными копиями; он содержит закрытые ключи. При смене IP потребуется обновить настройки подключения и коды семьи; автоматическая смена адреса пока не поддерживается.

Локальные записи редактора объединяются с общими. Для подключения на просмотр требуется подтверждение замены локальных записей общими. Существующие записи можно редактировать без интернета; изменения отправятся при следующем подключении. Синхронизация запускается после изменений, при открытии приложения, вручную и периодически в фоне (Android может задерживать фоновые задания).

Изменения разных записей объединяются автоматически. При одновременном изменении одной записи синхронизация останавливается: пользователь выбирает версии с этого телефона или с сервера **для всех конфликтующих записей**. До выбора данные не затираются. Если сервер меняется во время загрузки, приложение предлагает повторить синхронизацию.

Напоминания и часы периодов остаются настройками конкретного телефона. Для новых записей с другого устройства напоминания выключены. Полученные назначения сохраняют схему приёма и видны в календаре. Общий объём документов для синхронизации — менее 100 МБ, один файл — до 25 МБ, текстовый список — до 2 МБ. Каждая синхронизация скачивает полный архив; сервис рассчитан на небольшую семейную историю.

## Доступ и восстановление

Владелец приглашает людей и отключает устройства. Редактор добавляет, изменяет и удаляет записи. Просмотр разрешает только загрузку. Токены устройств случайные; сервер хранит их хеши. Токен и ключ телефона защищены Android Keystore.

Код восстановления позволяет вернуться с тем же токеном и ключом, в том числе восстановить владельца. Это полноценный секрет доступа. Не используйте его как приглашение: старый и новый телефон будут иметь одну серверную идентичность. Для дополнительного телефона создавайте приглашение. Если все коды и ключи потеряны, расшифровать архив невозможно.

Отключение в приложении оставляет локальные записи и удаляет настройки подключения. Оно не отзывает серверный токен; при потере телефона отключайте устройство со стороны владельца. Отзыв закрывает дальнейший доступ к сервису, но не удаляет уже скачанные данные и не меняет ключ семьи. Бывший участник знает старый ключ. При подозрении на утечку нужен новый сервис/семья и новые приглашения; автоматическая смена ключей пока не реализована.

Сервер видит IP-адреса соединений, названия устройств, роли, размер архива и время запросов. Шифрование содержимого не скрывает эти сведения. Обновляйте ОС/Docker и ограничьте SSH. Python-сервис закрыт внутренней Docker-сетью и имеет лимиты памяти/процессов; сервис не предназначен для публичной регистрации пользователей.

## Резервная копия

Сделать согласованную копию SQLite, пока сервер работает:

```sh
docker compose exec relay python backup.py /data/care.sqlite /data/care-backup.sqlite
docker compose cp relay:/data/care-backup.sqlite ./care-backup.sqlite
chmod 600 care-backup.sqlite
```

Хранить копию вне VPS, отдельно от кода восстановления. В ней зашифрованные данные, хеши токенов, устройства и приглашения. Для восстановления остановить relay, заменить `/data/care.sqlite` копией, запустить relay. Если рядом остаются `care.sqlite-wal`/`care.sqlite-shm`, не смешивать их со старой копией: восстановление выполнять в пустой том данных. Код восстановления владельца, адрес с портом и сохранённый центр сертификации Caddy должны соответствовать восстановленной семье.

Проверки сервера: `python3 -m unittest discover -s . -p 'test_*.py' -v`.
